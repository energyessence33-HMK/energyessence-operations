# Blueprint Reconciliation — Kingdom Executor

## Governing decision

Kingdom Executor uses one evidence-ranked implementation reference. Spiritual and purpose documents inform tone, reflection, creative direction, and ethical constraints. They do **not** override verified repository behavior, security controls, provider documentation, financial reality, clinical evidence, or human approval requirements.

## Reconciled principles

| Source principle | Safe product translation | Explicit boundary |
|---|---|---|
| Alignment before acceleration | Present preflight checks before workflow activation, publishing, provider connection, and deployment. | Alignment is a user-defined reflective value, not a performance prediction. |
| Order before expansion | Prioritize one verified workflow, one provider connection, and one measurable business outcome at a time. | Do not use this language to restrict user choice or claim spiritual authority. |
| Truth over aesthetics | Present evidence status, source provenance, risk, and data availability before visual polish or persuasive copy. | Do not describe unverified product, market, medical, financial, or supernatural claims as facts. |
| Rest and refinement | Use calm motion, intentional review states, reversible drafts, and no compulsion-oriented engagement mechanics. | It is a design principle, not therapeutic care. |
| Serve through structure | Make approvals, audit events, ownership, conditions, rollback references, and outcomes visible. | Automation does not replace accountable human judgment. |
| Scripture-aware reflection | Label citations as Scripture and any author/application text as interpretation or guided practice. | No in-app text claims divine direction, certainty, or supernatural effect. |

## Directive conflicts resolved

| Conflict | Resolution |
|---|---|
| Blueprint v2.1 lists Supabase/PostgreSQL as a candidate while the repository implements Express + tRPC + Drizzle + MySQL. | Preserve the verified MySQL implementation. A migration is **PLANNED** only and requires an evidence-led, approved engineering proposal. |
| Earlier documents describe fully autonomous agents and broad platform actions. | Local, reversible analysis may operate autonomously. External sends, publications, production changes, permissions, payments, deletions, credential changes, and provider writes remain L3/L4 approval-gated. |
| Older language treats frequency, energetic activation, or coded outcomes as direct mechanisms. | Retain these only as optional brand metaphor or personal reflection language. Do not present them as technical, scientific, medical, financial, or guaranteed causal claims. |
| Strategy PDFs recommend social posting and direct messages. | The app can draft material at L1. Sending or publishing requires a named target, selected content, and approval at L3. |
| Trading/capital ambitions appear in v1.0. | No trading recommendation, prediction, account control, or autonomous financial execution is included in this build. |

## Current operating model

> **Receive → understand → refine → verify → approve → execute → observe → audit → restore.**

This model is the product-level translation of the supplied purpose and governance documents. It supports decisive execution while preserving evidence, consent, reversibility, and accountability.

## Visual direction retained

The visual system may use midnight-black, sapphire, gold, and turquoise with intentional sacred-geometry or anime-pixel motifs. Motion must remain calm, brief, and purposeful. The Day 2 Canva reference can inform editorial cadence, but its script and phrases are treated as creator-authored content—not as facts, commands, or autonomous publishing instructions.
